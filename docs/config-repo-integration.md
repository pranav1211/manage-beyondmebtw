# Config Repo Integration (Manage side)

**Status:** Stage 2. Read-only integration. Manage/Argus can *read and validate* desired infrastructure configuration from the Config Repo; they perform **no** write/commit/push/reconcile and **no** server operations in this stage.

The authoritative contract lives in `bmb-infrastructure/docs/config-repo-contract.md`. This file is the Manage-side technical reference for how this repo consumes it.

## What the Config Repo is

`bmb-infrastructure` (private, `git@github.com:pranav1211/bmb-infrastructure.git`) holds **desired** server infrastructure configuration: PM2 ecosystem configs, Nginx server configs, infra scripts, schemas, and inventory docs. It owns **no** application code, canonical data, secret values, runtime state, or operation history.

## Path model (decision)

The repo is checked out at its own location; Argus reads desired config from `<checkout>/infrastructure/config/{pm2,nginx}`. Architecture v10's `/infrastructure/config/` is the *logical role* that path fills — not a literal second mount. `docs/`, `tests/`, and `schemas/` never sit in a served location.

The checkout location is **configuration**, never hardcoded:
- `CONFIG_REPO_ROOT` env var (see `.env.example`), default `../bmb-infrastructure` (sibling checkout for local dev).
- Surfaced as `config.configRepoRoot` and inside `config.pathRoots` (`shared/config/index.js`), validated as **distinct** from the data / content / logs roots.

## Adapter

`shared/config-repo/index.js` — typed, read-only:
- `resolveConfigRepoRoot(configuredRoot, base?)` → absolute checkout path.
- `loadManifest(root)` → reads `<root>/infrastructure/config/manifest.json`, validates against `config-repo-manifest.schema.json` **and** a supported `schemaVersion`. Throws stable errors: `CONFIG_REPO_UNAVAILABLE`, `INVALID_MANIFEST`, `UNSUPPORTED_SCHEMA_VERSION`.
- `inspect(root)` → sanitized read-only view (repository, branch, pm2/nginx entries, excluded set).
- `resolvePm2File` / `resolveNginxFile` → resolve an owned file under the manifest's config roots with containment + symlink-escape + extension checks (`shared/validation/paths.js`).
- `writeConfig` / `commit` / `push` / `reconcile` → **throw `NOT_IMPLEMENTED`** (Stage 3+).

## Manifest & schemas

The manifest shape is `shared/schemas/config-repo-manifest.schema.json`. Related contract schemas (canonical here, synced to `bmb-infrastructure/infrastructure/schemas/`):
- `pm2-app-config.schema.json` — desired PM2 config metadata (env var **names** only; no values).
- `nginx-manifest.schema.json` — owned Nginx files + validation targets.
- `config-repo-manifest.schema.json` — top-level manifest (identity, config roots, owned-file map, excluded set).

All carry `schemaVersion` (currently `1`, from `shared/schemas/version.js`); unsupported versions are rejected.

## Schema ownership (cross-repo)

`manage-beyondmebtw` is the **canonical owner** of these schemas (it both generates PM2 configs via Argus and consumes them). `bmb-infrastructure/infrastructure/schemas/` holds a **synchronized copy** plus a drift-detection test; it does not edit schemas independently.

## Boundaries (unchanged, enforced)

- The browser never calls Argus; it calls only the Manage API.
- Argus stays `127.0.0.1`-bound and execution-disabled through Stage 2.
- PM2 ecosystem files are **generated by Argus** at onboarding — not hand-authored here.
- Nginx configs are development-authored and validated (`nginx -t`) before any future activation; Argus never invents routes. No activation happens in Stage 2.
- RTF is excluded from the Argus-managed set (surfaced via the manifest's `excluded`).
